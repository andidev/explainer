# Pins Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add named, coloured pins: places on the board that you can jump to from chips in a new
bottom pin bar. You create a pin by dragging 📍+ onto the board, move it by dragging its chip or
marker, and rename or delete it from a right-click menu.

**Architecture:** Everything is in `index.html` (inline CSS/JS, the script is wrapped in an IIFE,
no build). Pins are part of the board state (`state.pins`). They are saved in localStorage, carried
in share links as an optional 6th packed element, and undoable through the existing
`commit()`/`restore()`. Markers live in a new `#pinLayer` inside `#world` and are counter-scaled to
a constant screen size. The pin bar is a new island, `#islPins`.

**Tech Stack:** Plain HTML/CSS/JS, no dependencies. Verification is by browser checks (in-app
browser tools) and headless Chrome for share links.

**Spec:** `docs/superpowers/specs/2026-10-13-pins-design.md`. Read it first; it is the authority.
Also read `CLAUDE.md` (code map and rules) and the Active entries in `DECISIONS.md`.

## Global Constraints

- One file, `index.html`; no dependencies. Colours come only from CSS tokens; the new pin colours
  are tokens `--pin-0` … `--pin-7` with dark values (spec §8).
- The packed link layout stays `[1, nextId, boxes, links, settings]`, with pins as an optional
  6th element `[[id, x, y, name, c], …]` written only when there are pins. The format version
  stays `1`. Old links and stored boards load with `pins: []` (spec §7).
- Every pin change is one `commit()` (one undo step). Creating a pin and then changing its name
  is two steps; an unchanged name adds none.
- Existing gestures keep working: right-click or middle-drag on empty board pans, Space+drag pans,
  box/line/marquee gestures, and every shortcut in `#help`.
- Nothing overlaps at 375, 800 or 1440px. There is no horizontal page scroll at 375px.
- Copy is in sentence case, with no exclamation marks.
- Do not edit `DECISIONS.md`, `README.md` or the `#help` text before Task 4.

## Review Focus

1. **Pin presses must not reach board gestures.** Pressing, clicking or right-clicking a marker
   must not start a marquee, pan, deselect or create a box (double-click). Pressing a chip must
   not either. Tasks 1–3 each check this.
2. **Old data.** A localStorage board without `pins`, and a v1.1.0 share link, must load with no
   errors. Every code path that reads `state.pins` copes with it missing until it is normalised
   (Task 1).
3. **Undo/redo consistency.** Creating, renaming, moving, deleting and clearing pins each undo in
   one step, and redo restores them. Undo/redo while a chip is being renamed must not corrupt
   the name (Task 2).
4. **Phone width.** At 375px the pin bar, its chips and the pin menu fit on screen without covering
   the other islands (Tasks 1–2).
5. **Many pins.** With 10 or more pins, the colours cycle and the bar scrolls without growing over
   the other islands (Task 2).
